## 推薦架構

Cloudflare Pages與Netlify各提供一個前端入口；/api與/assets代理到同一個具HTTPS、持久磁碟與隔離轉檔的後端。兩站共用教室代碼與資料；登入Cookie各屬自己的網站，換入口需重新登入／加入。

目前Node伺服器依賴本機檔案保存及Docker文件轉檔，不能直接把public/上傳後就當成完整平台。若改為Cloudflare全雲端服務，需進一步將保存遷移到D1／R2等儲存，並建置Containers轉檔；這是另一個後端遷移階段。Cloudflare Containers屬Workers付費方案相關資源，本輪未開通或建立付費資源。

## 已交付

- scripts/prepare-hosting.mjs：產生兩平台獨立輸出，僅複製public，排除伺服器、密碼及學生資料。
- Cloudflare：Functions middleware與_routes.json，只代理/api/*與/assets/*，保留Cookie與Authorization，敏感回應禁止快取。
- Netlify：netlify.toml、_redirects及安全標頭。
- 後端：ALLOWED_ORIGINS精確允許雙站來源，維持原本跨站請求防護。
- hosting.test.mjs：驗證HTTPS網址要求、敏感檔不發布、代理路徑、Cookie及不快取。

## 產生正式套件

先有通過驗收的HTTPS後端，再在專案根目錄執行：

```sh
node scripts/prepare-hosting.mjs https://實際後端網域
```

輸出dist/cloudflare和dist/netlify，已加入Git忽略。不可將範例網域當作正式後端發布。

後端環境變數：

- PUBLIC_ORIGIN=https://實際後端網域
- ALLOWED_ORIGINS=https://實際專案.pages.dev,https://實際專案.netlify.app
- DATA_DIR=專用持久資料目錄
- TEACHER_PASSWORD=由主機秘密管理注入
- 正式環境不可設定DEVELOPMENT_LOCAL_CONVERTER=1。

## 部署（名稱與後端完成後）

在dist/cloudflare內：

```sh
wrangler pages deploy public --project-name 實際專案名稱 --branch main
```

在dist/netlify內：

```sh
netlify deploy --dir public --site 實際專案ID --prod
```

先建立或連結正確專案；本輪未執行上述發布指令。部署後分別從兩個網址驗證教師登入、入課、跨站課堂同步、上傳、手寫及備份。

## 必須保留的限制

- Netlify代理有26秒逾時；此平台轉檔採非同步工作，轉檔本身不會占用同一請求，但大檔上傳時間仍需驗證。200MB單檔不能直接當作雲端可用容量保證；正式大檔上傳應補分段續傳或專用上傳通道。
- Cloudflare入口亦受方案的HTTP請求大小限制；部署驗收需以實際帳號與檔案測量。
- 本機Docker尚未就緒，容器配方並不等於隔離轉檔已驗證。
- 本輪不會把公開但API無法使用的外觀頁，當成完成部署。
